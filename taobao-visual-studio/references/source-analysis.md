## 1. liangdabiao/ecom-details-image
**流程**：判断任务 → 匹配 25 个场景模板 → 补关键缺失 → 视觉简报 → 多图建 Style Lock → 转化驱动力诊断 → 5 主图 + 7-9 详情 → 选生图通道（Codex imagegen / apiz CLI）→ 返回 Prompt 与文件。
**特点**：
- 「GPT-Image 铁律」：hex 色、产品占比数字化、显式留白、具体否定清单、平台预留区、3 层信息架构
- 多角度/景别强制规则（主图 ≥3 角度、详情 ≥4、不连续 3 张同角度、全景 ≤40%）
- 「详情页 ≠ 多角度产品照」，必须是信息图；中文「」引号提升渲染准确率；背景色交替
- 常见翻车点表
**不足**：字体规则偏奢侈品画册（衬线+无衬线）；默认图标化信息图，易显模板感。

## 2. coolqoo/1click-ecom-detailpage
**流程**：最小输入解析闸门（用户 > 追问 > 联网 > 推理 > 默认）→ 驱动力诊断 → Buyer Reason Card → 英文基准 → 本地化 → Style Lock → Product Angle Sheet → Image Copy Gate → Prompt/出图 → 自审评分卡。
**特点**：
- 信息来源标签（User-provided / Web-researched / Inferred / Assumption / Default）+ 假设披露
- Buyer Reason Card 锁定"为什么现在买"
- Product Angle Sheet：先生成多角度身份锁定图，再作为所有正式图的参考 —— 产品一致性最佳实践
- 每张图先定文案再写 Prompt；自审评分卡
**不足**：面向跨境英文；默认关闭合规并允许生成模拟好评/虚拟背书（**本 Skill 不采纳**，与中国《广告法》冲突）。

## 3. wzj177/ecommerce-image-suite
**流程**：API Key 预检 → 判断是否已上传图 → 视觉分析生成卖点 JSON（可编辑）→ 强制询问平台 → 选 8 类标准套图 → 模特判断与锁定 → 风格模板推荐（6 套）→ 多供应商生图 → 可选平台文案/详情 HTML/视频。
**特点**：
- 国内平台尺寸表（淘宝/京东/拼多多/抖音）
- 标准套图类型清单（白底、核心卖点、单卖点、材质、场景、模特、多场景拼图、详情图）
- 单图自动补「三角度拼图」；同批次模特锁定；6 套风格模板 × 图类型效果矩阵
- 国内多供应商（通义/豆包/Gemini/OpenAI）
**不足**：流程重、依赖大量脚本与 Key；卖点图偏图标化。

## 4. buluslan/gpt-image2-ecommerce
**流程**：意图识别 → 场景路由（39 模板，按需加载）→ 驱动力诊断 → 套图 Lock → 5-slot 组装 → 模型路由（快/精）→ imagegen.sh → 合规预检脚本 + 视觉质量自检。
**特点**：
- 5-slot Prompt：Scene / Subject / Important details / Use case / Constraints
- 文字渲染三招 + 无字底图兜底；edit 类 preserve 清单
- `compliance_check.py`：白底检测、前景占比、OCR
- anti-slop 双层（Prompt 禁用词 + 出图视觉检查 8 类 AI 痕迹）；「一轮一改」
- 红线：不复刻真人、不剥离 C2PA、不冒充实拍
**不足**：面向跨境平台（Amazon/TikTok），没有淘宝规范与《广告法》。

## 5. oldred-byte/ec-visual-skill
**流程**：分析商品/参考图角色 → 信息路由（只问一次）→ 保留用户给定屏结构 → 消费者视角地图 → 参考图提取视觉 DNA → 品牌/产品优先配色 → 每屏写 Picture Solo Statement → 按信息决定产品是否出镜 → **主图+详情统一审批表** → 逐张出图 + 验证。
**特点**：
- 「画面独立测试」：遮住文字画面仍能传达信息
- 消费者口吻文案，拒绝说明书腔
- 参考图是"语言不是场景"（场景元素 ≤30%）
- 多样性下限（5 主图 ≥4 主视觉，10 屏 ≥7）；任务目录隔离
**不足**：完全禁止图标偏激进；无平台尺寸/白底/违禁词自动检查。

## 共性
驱动力诊断（3 选 1）、多图风格锁、按需加载模板、参考图保一致性、出图前用户确认、无 Key 时降级为 Prompt 包。
